# Semantic catalog format

The catalog gives MCP-connected agents *semantic* understanding of patterns, effects, and
modulators — what a class does visually/algorithmically and how its parameters interact.
Structural facts (parameter names, types, ranges, options, descriptions) are **never**
recorded here: the live tools (`get_parameter`, `list_available_*`) own structure and are
always current.

**Catalog entries are a cache of source understanding, keyed by content hashes.** They are
generated by the [`lx-mcp-catalog` skill](../.claude/skills/lx-mcp-catalog/SKILL.md), never
hand-maintained — hand-maintained docs drift silently; hashed generated docs go *detectably*
stale instead.

## Location

One markdown file per class, named by fully-qualified class name:

```
package/src/main/resources/catalog/<fqcn>.md
e.g. package/src/main/resources/catalog/heronarts.lx.pattern.color.GradientPattern.md
```

`resources/` makes each entry a plain Maven resource — it ships inside the plugin jar and
the runtime serves it from the classpath. **Only stock LX entries live here**: baking
content-repo docs into the lx-mcp jar would couple its releases to every content package.

At runtime the resolution order for a class's entry is:

1. **`~/.lx-mcp/catalog/<fqcn>.md`** — the machine-local overlay. Where content-repo
   entries land when generated from local source (e.g. Apotheneum), and how any entry is
   refreshed without rebuilding a jar. Always wins: it is by definition the newest.
2. **The class's own jar** — `clazz.getClassLoader().getResourceAsStream("catalog/<fqcn>.md")`.
   A content package can ship its own catalog inside its jar (generated by the same
   skill, packaged under `catalog/` in its resources): docs travel with the code they
   describe, and a drop-in jar arrives documented with zero lx-mcp involvement. Because
   Chromatik loads package jars in a child classloader, resolving through the class's
   *own* loader finds these — the same loader rule the bytecode hash uses.
3. **The lx-mcp jar** — the stock LX entries generated in this repo.

A class with no entry at any tier is simply *undocumented* (`documented: false` over
MCP) — never fabricate an entry for a class whose source is unavailable.

## Frontmatter

Flat `key: value` scalars only (the runtime parser is deliberately not a YAML
implementation — no nesting, no multi-line values; `tags` is comma-separated):

```markdown
---
class: heronarts.lx.pattern.color.GradientPattern
kind: pattern                      # pattern | effect | modulator
sourceRepo: LX                     # logical name; sources.json maps it to the GitHub URL
sourcePath: src/main/java/heronarts/lx/pattern/color/GradientPattern.java
sourceSha256: <64 hex>             # source file at generation time — the generator's incremental key
classBytesSha256: <64 hex>         # .class bytes at generation time — the runtime staleness key (optional)
classBytesOrigin: ~/.m2/repository/com/heronarts/lx/1.2.1/lx-1.2.1.jar
lxVersion: 1.2.1
generatedAt: 2026-07-09T00:00:00Z
generator: lx-mcp-catalog/1 (<model>)
tags: color, gradient, palette
---
```

## Body: three fixed sections

```markdown
## Summary
One paragraph: what this renders / does, visually and algorithmically.

## Parameter interactions
How the knobs interact and which combinations matter — NOT a parameter list
(names/ranges/options come from get_parameter, live).

## Usage tips
When to reach for it, what it pairs well with, gotchas.
```

The runtime splits on these exact headings. Content rules for generators:

- Describe **behavior**, not structure. Never restate parameter names/ranges/defaults —
  they can drift, and the live tools already answer that. The line: describing *what a
  mode does* ("wrap modes clip or reflect the chase at strip ends") is in scope — bare
  enumerations of names/values/ranges are not.
- **Every mechanism claim must be verified against the source** — the order of transform
  stages, which buffer is written, what a parameter scales. A confidently wrong mechanism
  is worse than no entry. Never reference a parameter that does not exist in the source.
- Plain prose, one solid paragraph per section. Written for an LLM audience: precise
  verbs, no marketing language.
- `tags`: behavior vocabulary (motion, color, audio-reactive, geometric, texture,
  masking, strobe, utility, …), lowercase, comma-separated.

## Staleness semantics (served by `get_component_doc`)

The runtime hashes the **loaded class bytecode** (via the class's own classloader) and
compares it to `classBytesSha256`:

- `stale: false` — bytes identical to generation time. Trustworthy: identical bytecode
  means identical behavior.
- `stale: true` — bytes differ. The doc *may* still be accurate (recompilation without a
  source change can flip this); erring toward stale is deliberate. Regenerate.
- `stale: "unknown"` — the entry has no recorded hash, or the class bytes aren't readable.

`sourceSha256` is not consulted at runtime — it is the generation-side key that lets the
skill skip classes whose source hasn't changed.
